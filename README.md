# Insignia Court app

Expo / React Native customer app for rooms, dining, concierge services and boutique orders. The backend and owner/operations portals live in `insignia-mobile-backend`.

## Development

Run `npm ci`. Copy `.env.example` to `.env.local` and set `EXPO_PUBLIC_API_URL` to the backend API URL accessible from your device, including `/api`. Start with `npm start`.

## Checks and web build

- `npx tsc --noEmit`
- `npm run build` — creates the static web export under `dist`; production builds require an HTTPS API URL.

CI uses `https://example.invalid/api` solely to compile the app. Rebuild with the actual backend URL before deployment; do not deploy the CI sample configuration.

For web payments configure backend `FLW_WEB_RETURN_URL` to the exact public `/payment-complete` URL generated by the storefront. Only that URL and the registered native `insignia://payment-complete` callback are accepted. The return screen always asks the backend to verify payment; callback query status is not proof of payment.

Native notification delivery needs an Expo/EAS project ID, application identifiers, platform push credentials and physical-device acceptance. Rebuild native apps after changing the URL scheme or plugins. Room access uses reception handover; no automatic door unlocking is integrated.

Direct bank-transfer evidence and finance approval currently apply to room reservations only. Other purchases use Flutterwave, including any bank-transfer options it offers. Inventory, featured products and active-stay cards use backend records.
